\section{Purpose}
This document describes the directory constraints and implementation rules used
by automation projects. These rules establish a predictable project layout so
source files, \glspl{report}, test input data, and Ruby software components can
be found consistently by people and automation.

\tlcVspace%

\section{Scope}
This document is limited to \fk's \team\ automation project layout. It does not
provide governance or guidance for manufacturing systems, nor does it replace
the \gls{qms}. The scope is limited to the repository, report, factory, and Ruby
software organization used by projects that adopt the \af.

\tlcVspace%

\section{Project Structure}
The following sections describe the overall project structure, the report
structures used to create \docControl\ reports and records, the test input
factory that is used to test the application, and the Ruby software
organization that implements the \af.

\tlcVspace%

The project structure is presented first as a complete tree and then as focused
subsections. Each subsection explains one part of the tree and identifies which
folders are required, which are conventions, and which provide supporting
\gls{configuration-item} content for automated execution.
